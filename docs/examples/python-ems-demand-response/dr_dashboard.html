A supervisory demand-limiting controller, authored as Python EMS and tuned in three simulated iterations

A staged load-shed controller — written in Python, injected into EnergyPlus with create_python_plugin, revised twice with edit_python_plugin — watches whole-building electric demand every 10 minutes and ratchets zone cooling setpoints up (+1 / +2 / +3 K) whenever demand crosses a shed threshold. On a 10-zone office with a VAV + chiller plant in Boston, the final controller cut the summer billing peak by 7.2% and threshold exceedances by 73% while saving 3.9% energy.

How it was built — every step through MCP tools

  1. create_baseline_osm → add_baseline_system(system_type=7) — 10-zone, 2-story office; VAV with reheat, chiller + boiler plant.
  2. change_building_location(Boston TMY3) → set_run_period(Jun 1 – Aug 31).
  3. add_output_variable (facility demand, zone temps, thermostat setpoints, OAT at timestep) + add_output_meter (facility / cooling / fans electricity).
  4. run_simulation — baseline characterization; true peak 337.7 kW → shed threshold set at 82% (276.9 kW).
  5. list_ems_actuators(component_type="Zone Temperature Control") — confirms a Cooling Setpoint actuator per zone from the EnergyPlus .edd dictionary.
  6. create_python_plugin(template="custom", class_name="DemandLimiter", global_variables=["dr_stage"]) — full controller source below; the tool wires PythonPlugin:Instance/Variables/OutputVariable and validates the code against the plugin contract.
  7. save_osm_model → run_simulation → extract_simulation_errors (verifies PythonPlugin: Class DemandLimiter imported, zero severe errors).
  8. edit_python_plugin ×2 — controller revisions from simulated evidence (see table below).
  9. query_timeseries — demand, plugin stage output, setpoints, zone temps for every figure on this page; extract_summary_metrics / extract_end_use_breakdown for totals.

Findings a researcher would chase next

  
    
    
  • Shed capacity is finite: at stage 3 (+3 K) the floor is ~285–295 kW; deeper cuts need pre-cooling, chiller demand limiting, or lighting/plug DR — all writable as further plugin logic.
    • 
    
  • Chiller-staging transients: demand limiting induced brief plant cycling spikes (up to +19 kW over baseline for one timestep). On a 30-min billing basis they wash out; sub-metered plant control would remove them.
    • 
    
  • Comfort trade: zones float to 26.9 °C during events. Reported unmet cooling hours improve (152.5 → 24.7 h) only because EnergyPlus scores comfort against the actuated setpoint — an artifact worth knowing about, not a comfort gain.
    • 
    
  • The baseline plant is capacity-limited: baseline zones already float ~0.5–1.5 K above setpoint on peak afternoons, which is why the sizing-day demand plateau (351 kW) never appears in the run period.
    • 
  


  
    
    
  • Model: openstudio-mcp 10-zone baseline (100 m × 50 m × 2 stories, ~10,000 m²), ASHRAE baseline System 7 (VAV, chiller + boiler), Boston-Logan TMY3, Jun 1 – Aug 31, 10-min timesteps.
    • 
    
  • "Billing peak" = maximum 30-minute rolling average demand, the basis most demand charges use; instantaneous curves shown in the figures.
